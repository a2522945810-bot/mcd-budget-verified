# 连接与真人验收

当前状态：本地候选和报价检查已实现，参赛者用 WorkBuddy 真实账号调用过业务工具并转交一笔算价记录；本项目尚未完成由同一客户端加载 Skill、生成候选并依次核价的端到端验收。安装Skill不等于连接MCP。

## 先连接官方MCP

1. 在自己的电脑打开 https://open.mcd.cn/mcp ，用手机号验证登录。
2. 在控制台按官网提示阅读协议、激活MCP Token。Token只填入自己客户端的凭证设置，不发到聊天，不放GitHub。
3. 使用支持Streamable HTTP的客户端。官方赛事首页提供WorkBuddy步骤：左侧“专家·技能·连接器”进入连接器，创建自定义连接器并配置MCP，保存后启用。若界面变化，以客户端实际页面为准。
4. 服务地址为 `https://mcp.mcd.cn`；鉴权为Authorization头，值为Bearer后接自己的Token。
5. `mcp-config.example.json`只展示环境变量占位符，不能保证所有客户端会自动展开。客户端若不支持变量，要在本机私有设置中填写真实值，公开配置始终保留占位符。
6. 将本项目目录作为本地Skill加载；不同客户端的安装入口需按其说明操作。ChatGPT Work内的个人Skill与WorkBuddy本地Skill是两套安装位置，保存到一个客户端不代表另一个已安装。

## 可选的独立连接诊断

有Python 3.10或以上时，在项目目录的交互终端运行：

```bash
python scripts/connect_mcp.py --prompt-token
```

凭证隐藏输入，仅在当前进程使用。不查询用户业务数据，不下单，不保存Token。此程序只初始化MCP并读取工具定义，用于诊断；完成连接不代表已通过真实配餐测试。

可用`--output private/tool-manifest.json`保存本机工具定义，先自己创建private目录。目标必须不存在，以免误覆盖。该目录不提交。缺少核心工具返回退出码3；网络、凭证或协议错误返回2；完整发现返回0。

程序固定连接官方域名且不跟随重定向，支持JSON/SSE响应、会话头、协议协商及工具分页；不实现旧HTTP+SSE兼容与流恢复。若服务协议变化，应更新程序或使用官方推荐客户端。当前协议行为仅通过模拟服务测试，不能写成官方兼容认证。

## 第一次真实测试

向已加载Skill且已连接MCP的客户端输入：

> 帮我在25元内选择一人到店取餐组合，不要可乐。先让我确认门店，实际查询可售菜单和可用券，再核验最多8个候选的价格。不要下单。

由参赛者确认门店。检查真实工具调用、报价的餐品数量、选项、金额单位、优惠条件；再用麦当劳官方页面核对同店同方式的购物篮价格（价格可能随时变动）。复测无券、预算过低、指定餐品缺货、凭证失效。不要用买一单来替代这几项验证。

记录测试日期、客户端版本、调用工具名称、脱敏截图、是否符合预算、失败原因。真实数据检查通过后才能更新MCP_INTEGRATION中的状态；没有数据就保持待验证。

## 故障处理

- 401：在官网检查或重新激活Token。
- 429：停止循环重试，稍后再试。
- 工具缺少、参数报错：重新读取tools/list实际schema，不能猜接口字段。
- 价格、门店、券条件不匹配：放弃该候选，说明核价失败。
- Python或客户端安装困难：回传不含凭证的页面截图/错误文字，按实际环境处理。
